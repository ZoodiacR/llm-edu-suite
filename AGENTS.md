# AGENTS.md

Instructions for coding agents (Claude Code, Codex CLI, opencode, Cursor...) working on this repository. Humans are welcome to read it too: it is the short version of how the repo works.

## What this repo is

An LLM engineering course: 31 notebooks numbered in study order (`notebooks/<topic>/NN_<slug>.ipynb`), the course package `llm_edu_suite/`, command-line scripts in `scripts/`, and bilingual docs (`docs/en`, `docs/es`). Every number in a notebook or a doc comes from an executed run.

## Commands

```bash
# environment (once): Windows `powershell -ExecutionPolicy Bypass -File setup_env.ps1`, Linux/macOS `bash setup_env.sh`
.venv/Scripts/python -m pytest -q -m "not ollama"        # fast tests, no Ollama needed (bin/ instead of Scripts/ on Linux/macOS)
.venv/Scripts/python tools/build_notebooks.py 18         # rebuild notebook 18 from its generator (clears outputs)
.venv/Scripts/python tools/build_notebooks.py --keep-outputs 18   # rebuild, keeping outputs of code cells whose source did not change
.venv/Scripts/python tools/run_notebooks.py 18           # execute it in place, saving outputs (NB_CELL_TIMEOUT=seconds per cell)
```

Notebook 27 runs with a second environment, `.venv-harness` (see `scripts/harness_run.py`).

## How notebooks are made

- **Never edit an `.ipynb` by hand.** Each one is generated by `tools/notebooks/nbNN_<slug>.py`. Edit the generator, rebuild, run.
- Result commentary is written **after** execution: generators hold `{{R_...}}` markers, replaced with text that matches the executed outputs.
- Every notebook ends with **Results** (a table of what was measured) and **In production** (how to use it at work), then a `Next:` pointer.
- Style rules are in `tools/notebooks/CONVENTIONS.md`: a lesson before the code, current non-deprecated APIs, comments that read like a person wrote them (no `# =====` banners).

## Rules

- **Measured numbers only.** Do not write a result, a speed-up or a cost you did not see in an executed output. If a technique does not help here, say so.
- **Docs in two languages.** A change to `docs/en/X.md` needs the same change in its Spanish twin in `docs/es/` (file names differ: `installation.md` ↔ `instalacion.md`, `glossary.md` ↔ `glosario.md`, ...).
- **Secrets.** `.env` holds API keys and is git-ignored: never print it, copy it into a notebook or commit it. Check for a key by name only.
- **Private notes.** `notes/` is git-ignored personal material: never commit it.
- **One GPU job at a time.** The reference machine has a 6 GB GPU: training notebooks and Ollama notebooks run one after the other, never in parallel (parallel runs make Ollama hang).
- **Numbering.** The notebook number is the study order and the topic folder comes from `TOPICS` in `tools/nb_utils.py`. Adding a notebook means a generator, a `TOPICS` entry, and updating the README table and both notebook guides.
- **Commits.** Small, with a message that says what changed and why; never push or tag without the maintainer's approval.
